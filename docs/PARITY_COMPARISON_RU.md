# Межплатформенный аудит паритета экранов и функций: Mihon против TachiyomiSY, Komikku и mihon-vue

> **Целевая версия**: `mihon-vue` (Vue 3, TypeScript, Vuetify 4 с нативными токенами MD3, Pinia, Vite)  
> **Эталонный бэкенд**: Suwayomi-Server (REST API v1 / GraphQL, коммит `e2ce828abb81f0f5ce1a3fb86194a2746b519c85`, наблюдаемая сборка `v2.4.2366-r2366`)  
> **Апстрим-эталон**: Mihon (коммит `446f6df82c390ab760802c2fce3b677bce3f31c1`)  
> **Эталонные форки**: TachiyomiSY (`eu.kanade.tachiyomi`), Komikku (`komikku`)  
> **Исключения**: Специфичные для NSFW/хентая парсеры (например, экраны E-Hentai/ExHentai, `filterLewd`). Внимание сосредоточено исключительно на базовых функциях для чтения манги общего назначения.

---

## Краткое резюме

В этом документе представлен поэкранный и пофункциональный архитектурный аудит, сравнивающий `mihon-vue` с оригинальным флагманским Android-клиентом (`Mihon`) и двумя ведущими функциональными форками под Android (`TachiyomiSY` и `Komikku`).

- **Реализуемо на фронтенде**: Вызывать `ChangeCategoryDialog` в `HistoryView.vue:requestFavorite`, если у пользователя созданы категории и не настроена категория по умолчанию. - **Ограничения бэкенда/платформы**: В REST API Suwayomi-Server (v1 / v2.4.x) отсутствует специальный эндпоинт `/api/v1/history` и отдельная таблица базы данных истории. `mihon-vue` динамически формирует историю из временных меток чтения глав. Полная очистка истории без сброса статуса прочтения всех глав на бэкенде Suwayomi невозможна.

- **Реализуемо на фронтенде**: Массовое переключение источников языковой группы в фильтре (`onClickSources`); эмодзи флагов Komikku на языковых метках и фиксированные заголовки групп; экран ленты отдельного источника (`SourceFeedScreen`).

#### Сводка различий категории 6
- **Ключевые особенности фронтенда**: Объединение двухстраничных разворотов (Одинарный, Двойной, Авто), сдвиг обложки, инверсия разворота, межкадровый отступ по центру и склеивание страниц на Canvas в единое изображение для буфера/сохранения/отправки полностью реализованы в `mihon-vue`. Умное масштабирование вебтунов (4:3, 3:2, 16:9, 20:9) и эвристики авто-вебтуна соответствуют Komikku.
- **Ограничения бэкенда/платформы**: Аппаратные клавиши громкости не могут быть перехвачены современными веб-браузерами из-за системной изоляции ОС. Параметры выреза дисплея определяются метатегом viewport браузера, а не оконным API Android.

- **Ключевые особенности фронтенда**: 100% паритет структуры интерфейса и виджетов на всех 8 экранах и диалогах. Мастер настройки полностью воспроизводит логику оболочки `InfoScreen` Mihon с валидацией шагов и выбором папки.
- **Ограничения бэкенда/платформы**: Suwayomi-Server не сохраняет суммарное время чтения в секундах (выводится заглушка «Нет данных»). Браузерное окружение не может производить установку APK-пакетов Android или управлять фоновым питанием ОС.

- **Ключевые особенности фронтенда**: Адаптивный макет `TwoPanelBox` (master-detail); мгновенный поиск по настройкам с сопоставлением хлебных крошек и переходом с подсветкой; более 20 палитр тем + выбор произвольного цвета из Komikku; облачная синхронизация WebDAV; экспорт библиотеки в CSV; экран приоритетной сортировки тегов.

### 2. Ограничения бэкенда и платформы (зависят от Suwayomi-Server REST / нативного Android)

| Категория экранов | Недостающая функция | Причина и ограничения |
| :--- | :--- | :--- |
| **1. Библиотека** | **Расписание блокировки категорий по биометрии** | В Android используются хранилище ключей Keystore и системные службы биометрии (`BiometricPrompt`). В веб-браузерах нет возможности запускать фоновые таймеры блокировки по расписанию без явных запросов WebAuthn. |
| **2. Обновления** | **Серверный триггер обновления библиотеки** | В REST API Suwayomi-Server v1 нет эндпоинта запуска асинхронного обновления библиотеки (`POST /api/v1/update`); обновление инициирует повторный опрос данных на стороне клиента. |
| **3. История** | **Выделенная таблица истории и полная очистка** | Suwayomi-Server не хранит отдельную таблицу SQLite `history`. Очистка истории на стороне клиента потребовала бы деструктивно сбросить статус прочтения всех глав на всём сервере. |
| **4. Каталог и поиск** | **Управление жизненным циклом расширений APK** | Suwayomi-Server работает в headless-режиме на JVM/Docker. Установка, обновление и удаление расширений происходят на стороне сервера и не могут управляться через стандартные REST-эндпоинты. |
| **4. Каталог и поиск** | **Мутации репозиториев расширений** | Suwayomi-Server не предоставляет эндпоинтов для сохранения сторонних URL репозиториев в свой конфигурационный файл. |
| **5. Карточка манги** | **Предпросмотр страниц (`PagePreviewScreen`)** | Требует расширений источников на Kotlin, реализующих интерфейс `PagePreviewSource`. Suwayomi не отдаёт миниатюры предпросмотра страниц по REST. |
| **5. Карточка манги** | **Бинарная загрузка пользовательской обложки** | Suwayomi-Server поддерживает редактирование метаданных тайтла, но не имеет REST-эндпоинта для прямой загрузки бинарных файлов обложек. |
| **6. Читалка** | **Навигация физическими клавишами громкости** | Современные браузеры блокируют перехват аппаратных кнопок регулировки громкости из соображений системной безопасности и изоляции медиа-контролов ОС. |
| **7. Ещё** | **Посекундные временные метки времени чтения** | Suwayomi-Server сохраняет даты `lastReadAt`, но не ведёт таймер затраченного времени на каждую главу. В `StatsView` корректно отображается заглушка Mihon `"Нет данных"`. |
| **7. Ещё** | **Подавление серверной истории в инкогнито** | В REST API Suwayomi-Server отсутствует концепция сессий инкогнито; подавление сохранения истории осуществляется строго на стороне клиента. |
| **8. Настройки** | **Discord Rich Presence (RPC)** | Десктопный RPC Discord работает через локальные Unix-сокеты или именованные каналы IPC, доступ к которым из браузера закрыт без локального системного демона. |
| **8. Настройки** | **Полное восстановление базы из `.tachibk`** | В Suwayomi-Server нет API для импорта и полной замены внутренней базы данных файлами Protobuf `.tachibk`. Клиент валидирует резервные копии в браузере и обеспечивает экспорт. |
