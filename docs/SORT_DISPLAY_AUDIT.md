# Sort/display file-level audit

Reference: Mihon `446f6df82c390ab760802c2fce3b677bce3f31c1`.

This is a targeted **behavioral audit**, not proof that all 190 presentation files have been implemented or validated. The previous [inventory](PARITY_AUDIT.md) lists coverage, not verified parity. Rows below name inspected source files and their concrete consequences. Comparator/preferences/domain files are included because inspecting visual composables alone missed the functional bugs.

## Material 3: what is established

`src/plugins/vuetify.ts` now uses Vuetify 4 native MD3 typography/elevation; the previous v3 `md3` blueprint import has been removed. See [the v4 migration record](VUETIFY4_MIGRATION.md). The app uses Vuetify components, self-hosted Roboto and rounded Material Symbols, and the pinned Mihon static light/dark color roles. This is a **Material 3-based web adaptation**, not Android Compose Material3 and not guaranteed pixel-perfect Mihon. Custom CSS and web components must still be validated individually. The old “Material-style” wording was not sufficient evidence of behavioral parity.

## Regression evidence

- `tests/unit/library-ordering.test.ts`: primary/tie comparator behavior, nullable values, all tri-state directions, independent defaults and persistence, per-category isolation, each chapter comparator and chapter mode-change direction.
- `tests/unit/library-details.test.ts`: four parallel requests per batch, deduplication, stale server response protection, explicit error/retry. Summaries remain in memory, not a local manga database.
- `tests/e2e/sort-display.spec.ts`: actual DOM card/chapter order, positive/negative/clear filtering, navigation/reload persistence, shared library/catalogue columns, independent badge visibility, 56px/40px list geometry and chapter-number display. Synthetic fixtures are isolated regression checks, not live acceptance evidence.
- `scripts/verify-sort-display-live.mjs`: explicitly supplied live server; each available non-random library comparator and all four chapter comparators in both directions, preferences reload, real unread exclusion, resume destinations and list geometry. All API arrays stay in memory; report contains check names rather than raw API dumps.
- `scripts/capture-parity-live.mjs`: mobile/desktop real-source screens, fonts/ligatures, image availability, horizontal overflow and read-only request guard. Captures are stored **outside** the repository.

## Known limitations, intentionally not hidden

- Last update is disabled, not approximated by metadata fetch time. Latest chapter uses maximum uploadDate; chapter fetch date uses maximum chapter fetchedAt. These additional sorts/bookmark filters need cached chapter GETs and may display progress or a missing-data warning.
- No tracker score/filter, scanlator filtering, native selection/bulk operations, category editing or complete native settings surface. History remains explicitly unimplemented.
- Random uses a stable browser seed/hash until reshuffled, not Kotlin PRNG's exact permutation.
- Native category/chapter preferences are not synchronized to the server. This client persists harmless UI flags, not chapter lists or credentials.
- Global downloaded-only mode locks the corresponding tri-state filter. Local source titles are included by library downloaded filtering, matching the inspected native rule.
- GET acceptance may populate Suwayomi's server cache. Guards prevent library/progress/bookmark/download mutations; this is not a zero-side-effect guarantee for cache reads.
- Native Android baseline screenshots and Android instrumentation were not available. CSS pixel geometry and automated real-server behavior checks do not prove pixel-level equality at every density or every Mihon screen.
